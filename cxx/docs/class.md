## namespaces

to prevent names from clashing
```cpp
namespace myspace {
void *malloc(size_t size) {
    /* my code */
}

int strlen(char *s) {
    /* my code */
}
} // end myspace

// These will not contaminate `malloc` and `strlen` from libc.
int l = myspace::strlen("abc");
void *m = myspace::malloc(42);
```

anonymous namespace is sort of similar to what `static` is in `C`, those functions will not be `#include "..."` during compilation.
```cpp
static void test_me() {}

// is the same as ...

namespace {
    void test_me() {}
}
```

namespace alias can be used to shorten long namespaces
```cpp
namespace rv = std::views;

auto something = vec 
    | rv::filter(...)
    | rv::transform(...);
```

## `explicit`
`explicit` keyword will force class initialization to be explicit.
```cpp
class MyClass {
public:
    MyClass(int i) : int_(i) {}

private:
    int i_;
};

// This is valid, because initializer has 1 argument int
MyClass mc = 42;

// buf if
explicit MyClass(int i) : int_(i) {}
// invalid
MyClass mc = 42;

// this is valid
MyClass mc {42};
```
This prevents implicit initialization, which makes code less readable.

## Const Correctness
Put `const` at the end of function signature to mark the function as a const function which means it will not modify any variables/state in the class. Const members can be used on both const and non-const objects. Non-const members can only be used on non-const objects.

## Special Member Functions
SMF usually automatically generated by compilers, including
- Default construction
- Copy construction `MyClass(const MyClass& mc)`
    + creates a new object from existing const reference
- Copy assignment `MyClass& operator=(const MyClass& mc)`
    + replace the existing object with other object
- Move construction `MyClass(const MyClass&& mc)`
- Move assignment `MyClass&& operator=(constMyClass&& mc)`
- Destruction

When to write SMF?

When default one generated by compiler doesn't work, eg, ownership problem, contains raw pointers, mutex, smart pointer, filestreams etc.

Rule of Three: If explicitly define (or delete) a copy constructor, copy assignment, or destructor, should you define or delete all 3. (If one exists, then all exists).

Rule of Zero: If default SMF works, then don't define any.

## Iterators
Custom iterator may look like 
```cpp
class Iterator {
public:
    // Below are iterator traits
    // Iterator category: input, output, forward, bidirectional, random access
    using iterator_category = std::forward_iterator_tag;
    // Value type
    using value_type = T;
    // Reference type
    using reference = T&;
    // Pointer type
    using pointer = T*;
    // Type to count how far between iterators
    using difference_type = int;

    reference operator*() const;
    Iterator& operator++();
    Iterator operator++(int)
    {
        auto copy {*this};
        ++(*this);
        return copy;
    }

    // This is optional to have
    pointer operator->() const {
        return &(operator*());
    }

    friend bool operator==(const Iterator& lhs, const Iterator& rhs) { ... }
    friend bool operator!=(const Iterator& lhs, const Iterator& rhs) {
        return not(lhs == rhs);
    }

};

```

How this looks like in a container,
```cpp
class Container {
    class Iterator {
        ...
    };

    using iterator = Iterator;

    iterator begin();
    iterator end();

    // For bi-directional iterator
    reverse_iterator rbegin();
    ...

    // For const iterator
    const_iterator cbegin();
    ...
};
```

To create reverse iterator `std::reverse_iterator<T>` can be used. It can automatically reverse a iterator.
```cpp
class Container {
    class Iterator {
        ...
    };

    using iterator = Iterator;
    using reverse_iterator = std::reverse_iterator<T>;

    iterator begin();
    iterator end();

    reverse_iterator rbegin() {
        return reverse_iterator { begin() };
    }
    ...
};
```
